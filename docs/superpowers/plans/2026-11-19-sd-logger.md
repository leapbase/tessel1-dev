# Tessel 1 SD Logger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A script pushed to Tessel 1 board 1 that logs temperature and humidity to `LOG.CSV` every minute and saves a camera photo as `IMGnnnn.JPG` every 5 minutes on the SD card, running on its own.

**Architecture:** Small CommonJS modules under `logger/`. The FAT32 logic (`fat32.js`) is pure: it talks to a block device object (`read`/`write` of 512-byte blocks), so it is tested on the Mac against an in-memory device and a real `hdiutil`/`fsck_msdos` image before it ever touches hardware. The hardware modules (`sdcard.js`, `climate.js`, `camera.js`) are lifted from the working raw scripts. `main.js` schedules the cycles.

**Tech Stack:** Tessel 1 runtime (Colony, ES5, no bitwise operators), `tessel` CLI 0.3.25 on Node 0.12 (`nvm use 0.12`); tests on the Mac run on Node 24 (`node --test`-free plain `assert` scripts so they also run on 0.12).

**Spec:** `docs/superpowers/specs/2026-11-18-sd-logger-design.md`

## Global Constraints

- No bitwise operators (`& | ^ ~ << >>`) anywhere in code that runs on the board: use `*256`, `%`, `Math.floor`.
- Board 1 ports: SD **A** (SPI, chip select pin `G1`, card detect `G2`), camera **B** (UART 115200, power `digital[2]`), climate **D** (I2C `0x40`, chip select `digital[0]` low).
- SD card: SDHC block addressing, FAT32, 512 bytes/sector, 64 sectors/cluster, 2 FATs.
- Never modify, delete or overwrite an existing file, never reformat. Only create `LOG.CSV`, `LOG2.CSV`, `IMGnnnn.JPG`.
- Log header and rows: `time,temp_c,humidity,note`, always four columns. Notes: `` (normal), `boot`, `sensor_err`, `photo_err`.
- Timestamp `YYYY-MM-DD HH:MM:SS` = `START_EPOCH` (substituted at push time) plus uptime.
- Write order: data, then FAT (both copies), then directory entry (size). Log size updated after every line.
- Photos stream in 128-byte camera chunks, buffered to 512-byte blocks.
- **First on-board write happens only on a spare or freshly formatted FAT32 card** (spec, "My calls"). Do not write to the populated card on port A until the user says so.

## Review Focus

- Card missing or not FAT32 at boot: log nothing, blink the LED, retry in 60 s (test: Task 5 boot-without-card run).
- `LOG.CSV` already exists (a restart, or an older run): append, do not rewrite the header (test: Task 2 append-to-existing).
- Existing `IMGnnnn.JPG` files: numbering continues after the highest (test: Task 2).
- Camera returns nothing or times out: `photo_err` row, no partial file left visible (test: Task 4/5).
- Root directory cluster has no free slot: photo skipped with `photo_err`, log keeps running (test: Task 2).
- Minute and photo cycles coincide (every 5th minute): both happen, log first (test: Task 1 scheduler).

**Interfaces:**

### Task 2: FAT32 writer over a block device

**Files:**
- Create: `logger/fat32.js`, `logger/test/memdev.js` (in-memory block device), `logger/test/fat32.test.js`, `logger/test/make-image.sh`
- Reference: `raw-sd-write.js` (FAT32 write order, directory slot search, FSInfo), `raw-sd-ls.js` (boot sector parsing, 8.3 name decoding)

**Interfaces:**
- Consumes: block device `dev` with `dev.read(lba, cb(err, Buffer(512)))`, `dev.write(lba, Buffer(512), cb(err))`.
- Produces: `fat32.mount(dev, cb(err, vol))`, where `vol` has:
  - `vol.find(name83: string, cb(err, entry|null))`, `entry = {name, size, firstCluster, dirLba, dirOffset}`.
  - `vol.highestImageNumber(cb(err, n))` (0 if none; scans `IMGnnnn.JPG` in the root).
  - `vol.create(name83, cb(err, entry))` (zero-length file; fails if the name exists).
  - `vol.append(entry, bytes: Buffer, cb(err, entry))` (extends the cluster chain as needed; updates FAT copies then the directory entry).
  - `vol.appendStream(entry)` returning `{write(chunk, cb), close(cb(err, entry))}` for photos: data and chain written as chunks arrive, directory size updated only in `close`.
- Errors are `Error` objects with `.code` in `{'NOT_FAT32','NO_SPACE','DIR_FULL','EXISTS','IO'}`.

- [ ] **Step 1: Write failing tests** in `fat32.test.js` against `memdev`, built from a FAT32 image made by `make-image.sh` (`hdiutil create -size 64m -fs MS-DOS -volname TESTSD -layout MBRSPUD` plus a `.dmg`-to-raw copy; the script prints the raw image path). Cases: mount OK and `NOT_FAT32` on a zeroed device; `create('LOG.CSV')` then `find` returns it; `append` 3 times and read back the exact bytes by following the chain; append across a cluster boundary (append 40 KB in 600-byte pieces) reads back identically; `appendStream` of 47,000 bytes in 128-byte chunks then `close` gives size 47000 and exact bytes; `highestImageNumber` with `IMG0001.JPG` and `IMG0007.JPG` present returns 7; append to a pre-existing `LOG.CSV` keeps the old content; `DIR_FULL` when the root cluster's slots are all used; existing entries (create 5 files first) byte-identical afterwards.
- [ ] **Step 2: Run** `node logger/test/fat32.test.js`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement** `fat32.js`. Follow `raw-sd-write.js` for write order and FSInfo; add: FAT chain walk, free-cluster search starting at the FSInfo hint, cluster-chain extension, 8.3 directory entries with creation date from `clock` is **not** needed (zero date is acceptable).
- [ ] **Step 4: Run** the tests. Expected: all pass.
- [ ] **Step 5: Run `fsck_msdos -n <raw image>`** on the image after the tests wrote to a copy of it. Expected: exit 0, no errors. Add this to `fat32.test.js` as a final check on macOS.
- [ ] **Step 6: Run under Node 0.12.** Expected: pass.
- [ ] **Step 7: Commit** `git commit -m "Add FAT32 append/create writer with Mac tests"`.

**Interfaces:**

- [ ] **Step 3: Run** `tessel run logger/spike-sd.js`. Expected: `SPIKE PASS size=14`, no crash. If the runtime crashes on the FAT code, stop and report the error text.

### Task 4: Climate and camera modules

**Files:**
- Create: `logger/climate.js`, `logger/camera.js`, `logger/spike-sensors.js`
- Reference: `raw-climate-test.js` (Si7005 reads, chip select), `raw-camera-photo.js` (VC0706 sequence)

**Interfaces:**
- Produces: `climate.read(port, cb(err, {tempC: number, humidity: number}))`.
- Produces: `camera.capture(port, sink, cb(err, byteCount))` where `sink = {write(chunk, cb(err)), abort()}`; the camera is powered, initialised, read in 128-byte chunks and powered off for each call. On any error it calls `sink.abort()` and `cb(err)`.

- [ ] **Step 1: Write `spike-sensors.js`**: read climate on D and print `tempC` and `humidity`; capture to a counting sink on B and print the byte count. Print `SENSORS PASS` when temperature is between -20 and 60 and humidity between 0 and 100 and the photo is over 5,000 bytes and starts with `FF D8`.
- [ ] **Step 2: Run** `tessel run logger/spike-sensors.js`. Expected: `SENSORS PASS`, values close to the earlier readings (about 24 C, about 33 %RH) and a photo of roughly 47,000 bytes.
- [ ] **Step 3: Unplug the camera and run again.** Expected: `camera.capture` calls back with an error within 5 s and the sink is aborted (no hang).
- [ ] **Step 4: Commit** `git commit -m "Add climate and camera modules"`.

### Task 5: Main loop

**Files:**
- Create: `logger/main.js`
- Consumes: `clock.format`, `clock.now`, `rows.*` (Task 1); `fat32.mount` and `vol` methods (Task 2); `sdcard.open` (Task 3); `climate.read`, `camera.capture` (Task 4).

**Interfaces:**
- Produces: running `logger/main.js` starts the logger. `START_EPOCH` is a top-level `var START_EPOCH = 0; // PUSH_TIME_PLACEHOLDER` line for the push script to replace.

Behaviour (decisions the spec fixes):
- Boot: open card, mount, find or create `LOG.CSV` (write header only when created; use `LOG2.CSV` if the existing entry fails sanity checks), write a `boot` row, cache `highestImageNumber`.
- Every 60 s: read climate and append a `reading` row, or a `note` row with `sensor_err`. At minutes divisible by 5 take a photo after the log row: create `IMG<n+1>.JPG`, stream the capture, close; on failure write `photo_err` and leave no directory entry.
- Whole startup and every cycle are inside try/catch; any failure logs `note` when the card is writable, blinks LED1 and retries after 60 s. The process never exits.

- [ ] **Step 1: Test the boot-without-card case:** remove the card, `tessel run logger/main.js`. Expected: console `no card, retry in 60s`, LED blinking, no exit; insert the spare card, within 60 s a `boot` row appears.
- [ ] **Step 2: Run a 12-minute soak:** `tessel run logger/main.js` with `START_EPOCH` set to the current time. Expected console: at least 12 `log` lines and 3 photo lines (minutes 0, 5, 10).
- [ ] **Step 3: Check the card on the Mac:** `fsck_msdos -n` clean; `LOG.CSV` has a header, a `boot` row and 12 rows with four columns each (check with `awk -F, 'NF!=4'` printing nothing); three `IMG000n.JPG` files open as JPEGs (`file` reports JPEG).
- [ ] **Step 4: Failure paths:** unplug the camera during a photo minute: expect `photo_err` and no new `IMG` entry. Unplug climate: expect `sensor_err` rows.
- [ ] **Step 5: Commit** `git commit -m "Add logger main loop"`.
